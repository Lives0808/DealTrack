## DealTrack v0.2.1 · 演示数据诚实性修复

补丁版本，修的是**我自己写的 bug**。

### 问题

种子脚本会打印「✔ 成交：QT-… → 已生成形式发票，**定金已收**、尾款逾期 9 天」，
但回款看板上「已收」永远是 **$0**。

原因：登记定金收款时用的是「按到期日筛选待收」的接口，而**定金三天后才到期** ——
所以那次查询永远查不到它，钱从来没有被登记过。

**消息在撒谎，而没有任何测试会发现这一点**，因为我写的是断言「流程跑通了」，
不是断言「数据是它声称的样子」。

### 修复

| 缺陷 | 后果 |
|---|---|
| 用 `dueMilestones()` 查定金 | 定金永不被登记，干净安装后回款看板显示「已收 $0」 |
| 控制台消息硬编码 | 打印「定金已收」而实际状态是 `pending` |
| `seedDealClosure()` 假定有常驻工作池 | 在无工作池的环境（如测试）里 PI 永远不会生成 |
| 回退尾款到期日后未立即对账 | 逾期状态依赖下一次扫描，种子数据不自洽 |

### 变更

- 定金按 ID 查询，不再依赖到期日
- 控制台消息改为**反映实际结果**（`depositPaid` 字段），而不是复述一句文案
- `seedDealClosure()` 新增可选 `pump` 钩子：有工作池时等它，没有时由调用方驱动队列
- 回退到期日后立刻 `refreshOverdueMilestones()`，种子数据不依赖扫描时机
- 冒烟测试新增【20】章节专门守护**演示数据自洽性**（**88 项**）

### 这个补丁说明的一件事

「测试通过」和「数据正确」是两回事。之前 84 项断言全绿，是因为它们检查的是
**流程有没有跑完**；没有一条检查**跑完之后数据是不是它声称的样子**。

现在有了。这是本轮「补缺点」里最值得记住的一条。
