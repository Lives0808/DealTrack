## DealTrack v0.2.2 · 外发内容正确性修复

**这一版是「真的把安卓 App 跑起来」跑出来的。**

我把 Release 里的 APK 下载下来、装进模拟器、连上服务端、点了一遍 ——
界面全部正常。但就在看服务端日志时，发现了一封**已经生成好的催款邮件**内容荒谬。

构建通过、安装成功、界面能开，都不代表**客户收到的东西是对的**。

---

### 修了什么

| 缺陷 | 你会看到什么 |
|---|---|
| **催款邮件被写成「感谢您的询盘」** | 离线拟稿器没有 `payment_reminder` 阶段，静默回退到「首封回复」——**要钱的时候发了一封感谢信** |
| **「感谢您就 {company} 发来的询盘」填的是客户自己的名字** | 变成「感谢您就**田中 健一**发来的询盘」。这句话指的是**他们问的产品**，不是他们是谁 |
| **催款正文混着英文标签** | 日语邮件里出现 `Payment: 168439.76`，数字还没有千分位 |
| **催款用了报价的 CTA** | 催款信里问「能否确认数量与目的港」——追钱的时候把订单问没了 |
| 未知阶段静默回退 | 任何新阶段漏配都会发出一封时机错误的邮件 |

### 改了什么

- 话术库新增催款三句式，**10 种语言完整**（英/中/西/法/德/俄/阿/葡/日/韩）
- 金额与日期按客户语言格式化：德语 `168.439,76 $` / `20. September 2026`，阿语 RTL `‏168,439.76 US$`
- 定金/尾款/分期款名称抽到共用层，报价单与催款信使用同一套翻译
- 未知阶段改为中性短消息，不再假装是第一封回复
- 冒烟测试 **88 → 92 项**，新增【21】章节守护**外发内容质量**

### 三版的教训连起来看

| 版本 | 修的是 | 怎么发现的 |
|---|---|---|
| v0.2.1 | 数据是不是它**声称**的样子 | 读自己写的种子脚本输出 |
| v0.2.2 | 发出去的内容是不是**人话** | 真的把 App 跑起来、打开看 |

两次都是「测试全绿」的情况下发现的。**测试能证明流程跑完了，证明不了结果值得发给客户。**
