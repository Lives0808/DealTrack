## 明确不做

| 不做 | 原因 |
|---|---|
| 做成通用 CRM | 通用 = 谁都不好用。DealTrack 只为「跨境小卖家询盘→报价→跟进」这一条链路优化 |
| 强制使用某个 LLM 供应商 | 会锁死用户，且不同市场/预算需求差异极大。坚持 BYOK |
| 云端托管客户数据（默认） | 客户名单就是小卖家的全部家当。默认本地，托管必须是**可选项** |
| 提前做多租户抽象 | 只有托管形态才需要。SQL 已按可迁移写，真要换是驱动层的事，不是数据模型的事 |
| 自动扣款 / 代收货款 | 涉牌涉证，交给专业支付通道 |
| 无人工确认的全自动外发（默认） | 一封错误报价的代价远高于省下的 3 分钟。默认人工兜底，自动是选项 |

## 怎么提需求

开 Issue 时请写清**场景**而不是**功能**，例如：

> ✅「德国客户常问 TÜV 认证，我每次都要翻文件柜找证书号」
> ❌「加一个证书管理功能」

场景能让我判断这件事该由智能体做、该进看板、还是根本不该做。
