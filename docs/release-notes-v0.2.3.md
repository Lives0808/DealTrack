## DealTrack v0.2.3 · 催款草稿可见性修复

补丁版本。**又是「真的在手机上看一眼」才发现的**：催款草稿生成了、内容也对了，但
**两个界面都看不到它**。

### 问题

我在模拟器里点开「跟进看板 → 待确认」，是**空的**。

原因：催款只创建了 `message` 记录，没创建 `followup`。而跟进看板列的是 `followups`
—— 所以那份内容完全正确的催款草稿，在 Web 控制台和安卓 App 里都是隐形的。

**没人看得见，就没人发得出去。** 一个看不见的草稿等于没生成。

顺带还查出三个：

- `sweep_due` 会把催款记录当成普通跟进重新起草 —— 发出一封关于欠款的「报价跟进」
- 同一个跟进缺少「已有待确认草稿」的判断，可能被重复起草
- **连点两次「催款」会生成两封一模一样的草稿**：扫描端按提醒次数去重，但手动按钮
  用了时间戳做 key。审草稿的人很可能把同一封催款信发两遍 —— 恰好是催款这件事
  最该避免的印象

### 修了什么

- 催款同时建立 `followup`（`intent: payment_reminder`）并关联消息 → **跟进看板立即可见**
- `sweep_due` 跳过回款类跟进：它归 `sweep_payments` 管，只有那边知道金额与到期日
- `draft_followup` 遇到已有草稿的跟进直接跳过
- 「催款」按钮改用稳定去重键，且同一笔欠款已有待确认草稿时直接跳过
- 冒烟测试 **92 → 95 项**，新增「可见性」「不重复起草」「重复点击」断言

### 连续三个版本，三种不同的坑

| 版本 | 修的是 | 怎么发现的 |
|---|---|---|
| v0.2.1 | 数据是不是它**声称**的样子 | 读自己写的种子脚本输出 |
| v0.2.2 | 发出去的内容是不是**人话** | 真的把 App 跑起来、打开看 |
| v0.2.3 | 东西**看得见**吗、会不会**重复** | 在手机上点「待确认」，发现是空的 |

三次都是在「测试全绿、构建通过、界面能开」的情况下发现的。

> **能跑通、内容对、看得见，是三件不同的事。**
> 自动测试只能证明第一件。

### 快速验证

```bash
tar xzf dealtrack-server-0.2.3.tgz && cd DealTrack
npm install && npm run build
npm run seed --workspace=server -- --with-samples
npm start                          # → http://localhost:8787

npm run smoke --workspace=server   # 94 项端到端断言
```

演示数据会推进一单成交（定金已收、尾款逾期 9 天），所以回款看板和跟进看板
打开就有内容。
